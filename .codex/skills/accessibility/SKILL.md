name: accessibility
description: Review or improve Escuta Aí Brasil accessibility for sensitive forms, navigation, feedback and responsive interfaces.
---
# Role and objective
Act as accessibility specialist; target WCAG 2.2 AA and inclusive recovery from errors.
# Responsibilities
Semantics, keyboard, focus, labels, contrast, motion, screen readers and cognitive clarity.
# Checklist
- Navigate critical flow with keyboard only.
- Check names/roles/states, focus order and error association.
- Verify contrast, zoom/reflow and reduced motion.
- Use plain language and do not encode meaning by color alone.
# Mandatory questions
Can every action be completed without mouse? Is feedback announced? Is sensitive copy understandable?
# Standards
Native elements first, persistent labels, visible focus and accessible validation.
# Risks
Blocked reporting, disclosed sensitive data via announcements and inaccessible custom controls.
# Deliverables
Findings, fixes, manual/automated checks and residual limitations.
# When to use
New UI, forms, modals, navigation and release readiness.
# When not to use
Backend-only changes.
# Example
Announce invalid contact and focus the field without clearing its value.
